# Viking 高校手册 Markdown

## 适用背景

本 skill 面向将高校本科生/研究生学生手册、学籍与培养规定、学生管理制度、奖助与处分办法等文档（如 PDF、DOCX、TXT、HTML 等），接入 Viking 向量知识库的场景。

目标是从源文档中提取全部有效正文内容，并保留正式制度文本及其层级关系，让知识库能按“制度—章节—条款”检索；避免原始文档无法直接切片、条款级过度碎片化、或固定长度切片割裂语义等问题。

## 输出规范

- 每个源文档生成一份独立 Markdown，从一级标题直接开始，例如：`# 同济大学研究生学生手册`。
- 不添加使用说明、转换说明、来源页码、提取元数据、前言，或“（向量知识库版）”等后缀。
- 保留原始有效正文、正式文件标题、章/节/条层级、列表、表格、附件、生效日期及版本信息。
- 使用 Markdown 还原层级：`#` 手册标题、`##` 制度/办法/指南、`###` 章、`####` 节、`#####` 条。
- 对 PDF、DOCX、TXT、HTML 等不同格式，均需提取全部有效内容并统一转为目标 Markdown。
- 移除封面、目录、页眉页脚、印刷页码、导航栏、广告区及提取噪声；只保留正文与必要的制度性附属内容。
- 不得为了压缩 chunk 数删除任何实质内容。

## Viking 分段规则

使用下列精确字符串作为独立一行的分段标识符：

```text
<!-- VIKING_CHUNK -->
```

- 小型文档、单主题通知、单流程说明等内容较短且语义连续的文档，默认尽量少切分；若没有明显必要，可以完全不插入分段标识符。
- 将标识符置于 `##` 制度标题之前；仅在语义足够独立的后续 `###` 章标题前添加。
- 默认将一个制度标题与其第一章合为一个 chunk；同一制度中连续的短章可继续合并。
- 不要因为标题层级完整就机械切分。对篇幅较短、上下文高度连续的文档，应优先保持为单一整体或极少数 chunk。
- 不在每个节或每条之前加标识符。条款必须保留为其所属 chunk 内的 `#####` 标题。
- 每份最终文档不得超过 **150 个 chunk**。计数时，若 Viking 会将首个标识符前的内容视为一个分片，也必须将其计入。
- 大型手册优先控制在约 100-145 个 chunk。若超限，合并同一制度内相邻章节的 chunk，不删除标题或正文。
- Viking 配置采用“按分隔符切分”，分隔符填写上述完整字符串。仅当单个 chunk 超过嵌入模型硬性输入上限时，再启用固定长度兜底切分。

## 处理流程

1. 提取源文档全部有效内容；若为 PDF，需抽查含表格、多栏排版、封面和标题页的页面；若为 DOCX、TXT、HTML 等，也需检查标题层级、表格、列表、附件及正文是否完整。
2. 从目录识别制度标题，防止正文中看似标题的普通句子被误判为 `##`。
3. 依据制度、章、节、条重建 Markdown 标题层级。
4. 先判断文档是否属于小型且单主题的内容；若是，则优先不插入分段标识符；仅在确有必要时，按制度和选定的章节边界插入分段标识符。
5. 统计实际 chunk 数，确保不超过 150，并检查是否存在过细切分，同时检查标题语义和正文完整性。
6. 交付 Markdown 文件，并说明每份文件的最终 chunk 数；若未插入任何分段标识符，也应明确说明。

## 最终形态示例

```markdown
# 同济大学研究生学生手册

<!-- VIKING_CHUNK -->

## 普通高等学校学生管理规定

(41号令)

### 第一章总则

##### 第一条

为规范普通高等学校学生管理行为，维护普通高等学校正常的教育教学秩序和生活秩序……
```
