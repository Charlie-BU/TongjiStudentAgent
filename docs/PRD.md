# 济星云「同济同学智能体」升级改造 PRD

## 1. 项目概述

| 项目项 | 内容 |
| --- | --- |
| 项目名称 | 济星云「同济同学智能体」升级改造 |
| 产品载体 | 济星云小程序内智能体入口 |
| 产品定位 | 面向全校师生的校园信息问答与服务导航智能体 |
| 首期重点 | 围绕 9 月入学节点，优先建设新生高频问题知识库与问答能力 |
| 重点服务对象 | 全校师生，其中首期重点覆盖本科及研究生新生 |
| 上线目标 | 9 月前完成首期上线，支撑新生入学阶段高频咨询需求 |

## 2. 项目背景

同济大学校园信息分布在多个渠道中，包括学校官网、学院官网、公众号、济星云、迎新系统、教务系统、新生群、小红书经验帖等。对于新生而言，最大的问题不是完全没有信息，而是：

| 问题 | 具体表现 |
| --- | --- |
| 信息来源分散 | 不同问题需要在多个平台中查找 |
| 信息准确性难判断 | 群聊、小红书、往届经验可能存在过期或不完整情况 |
| 适用对象不清晰 | 本科生、研究生、不同学院、不同校区的情况不同 |
| 缺少统一入口 | 用户不知道某类问题应该去哪个系统或哪个部门了解解决 |
| 真实问题难沉淀 | 新生群和社交平台中反复出现的问题没有被系统化整理 |

因此，本次升级希望把「同济同学智能体」作为济星云内的校园信息统一入口，首期借 9 月新生入学场景，完成一套可持续维护的知识库与问答机制。

## 3. 本次升级目标

| 目标 | 说明 |
| --- | --- |
| 建立统一校园问答入口 | 用户可以在济星云内直接询问校园相关问题 |
| 优先覆盖新生高频问题 | 围绕报到、住宿、系统、选课、校园服务等入学场景建设知识库 |
| 提升信息可信度 | 通过官方资料、学院资料、人工核验机制保证答案可靠 |
| 区分用户身份 | 根据本科/研究生、学院、校区等维度提供更匹配的回答 |
| 连接济星云服务 | 对于可办理事项，回答中提供济星云或官方页面跳转入口 |
| 沉淀长期知识库 | 首期服务新生，后续扩展到全校师生的校园信息问答场景 |

## 4. 首期核心场景

| 场景分类 | 典型问题 | 服务目标 |
| --- | --- | --- |
| 入学报到 | 报到需要带什么？什么时候到校？在哪里报到？ | 帮助新生完成入学报到 |
| 住宿生活 | 宿舍怎么查？能不能提前入住？宿舍报修在哪里？ | 解决住宿与生活问题 |
| 账号系统 | 统一身份认证怎么激活？校园邮箱怎么用？VPN 怎么开？ | 降低系统使用门槛 |
| 校园服务 | 校园卡怎么办？图书馆怎么进？哪里看校车？ | 引导使用校园服务 |
| 学习事务 | 本科怎么选课？研究生培养计划怎么看？培养方案在哪里？ | 帮助进入学习流程 |
| 学院信息 | 学院新生群在哪里？教学秘书怎么联系？学院通知看哪里？ | 减少学院信息差 |
| 校区交通 | 四平、嘉定、沪西怎么去？报到路线怎么走？ | 解决到校和跨校区出行问题 |

## 6. 知识库建设方案

本次项目的核心不是单纯接入已有文件，而是建立一套“问题发现—资料匹配—答案整理—人工核验—持续更新”的知识库建设机制。

### 6.1 信息来源

| 来源类型 | 具体来源 | 主要作用 |
| --- | --- | --- |
| 学校官方资料 | 本科生院、研究生院、学生处、信息办、后勤、图书馆、校医院等官网或通知 | 作为正式答案的主要依据 |
| 济星云已有功能 | 济星云内已有服务入口、办事页面、通知模块 | 用于生成跳转入口和操作指引 |
| 学院资料 | 各学院官网、公众号、新生通知、教学管理办公室信息 | 补充学院差异化内容 |
| 迎新相关系统 | 迎新系统、报到系统、宿舍查询、缴费系统等 | 提供新生入学关键流程信息 |
| 新生群 | 本科/研究生新生群中的高频提问 | 用于发现真实问题，不直接作为正式答案 |
| 小红书/社交平台 | 同济新生搜索结果、经验帖、评论区问题 | 用于发现信息差、表达方式和高频焦虑点 |
| 人工访谈 | 学长学姐、新生、辅导员、教学秘书 | 补充实际流程、常见误区和表达方式 |

### 6.2 知识获取流程

| 步骤 | 说明 | 输出物 |
| --- | --- | --- |
| 1. 问题收集 | 从新生群、小红书、往年 FAQ、当前智能体测试中收集问题 | 原始问题池 |
| 2. 问题归类 | 按照报到、住宿、系统、学习、学院、交通等分类整理 | 问题分类表 |
| 3. 高频筛选 | 筛选重复率高、影响面广、入学阶段紧急的问题 | 高频问题 Top 100 |
| 4. 官方资料匹配 | 为每类问题寻找对应官方文件、通知或系统入口 | 资料来源表 |
| 5. 答案整理 | 将官方内容转化为适合问答的简洁答案 | 标准问答内容 |
| 6. 人工核验 | 由产品/运营/相关部门确认答案准确性 | 可上线知识条目 |
| 7. 知识库录入 | 录入知识库，并标注适用对象、来源和更新时间 | 正式知识库 |
| 8. 持续更新 | 根据用户反馈和未命中问题补充内容 | 知识库迭代记录 |

### 6.3 知识条目字段

| 字段 | 说明 |
| --- | --- |
| 问题标题 | 如“新生如何激活统一身份认证” |
| 问题分类 | 报到 / 住宿 / 系统 / 选课 / 校园服务等 |
| 适用对象 | 本科生 / 研究生 / 全体学生 |
| 适用学院 | 全校通用或具体学院 |
| 适用校区 | 四平 / 嘉定 / 沪西 / 沪北等 |
| 标准答案 | 整理后的简洁回答 |
| 操作步骤 | 具体应该怎么做 |
| 相关入口 | 济星云入口或官方链接 |
| 信息来源 | 文件、官网、公众号或系统名称 |
| 发布时间 | 来源内容发布时间 |
| 核验时间 | 最近一次人工确认时间 |

## 7. 智能体回答要求

| 要求 | 说明 |
| --- | --- |
| 优先回答结论 | 避免用户需要自行从长文本中提取答案 |
| 标明适用范围 | 说明答案适用于本科、研究生、某学院或某校区 |
| 提供操作步骤 | 流程类问题需要告诉用户下一步怎么做 |
| 提供相关入口 | 能跳转的事项尽量给出济星云或官方入口 |
| 展示信息来源 | 重要信息需要展示来源和核验时间 |
| 不确定时不编造 | 知识库没有依据时，引导用户查看官方渠道或提交反馈 |

### 后续版本再考虑

| 能力 | 暂缓原因 |
| --- | --- |
| 个人成绩/课程记录接入 | 涉及权限与数据合规，首期不建议做 |
| 复杂培养方案自动分析 | 开发成本较高，适合二期 |
| 课程推荐 | 需要课程评价和个人目标数据支撑 |
| 转专业成功率判断 | 缺少可靠数据，容易误导用户 |
| 社区经验内容展示 | 需要审核机制，首期可先收集不展示 |

## 13. 项目核心结论

本次升级不是重新开发一个单独的新生产品，而是在济星云现有「同济同学智能体」基础上，完成一次校园信息服务能力升级。首期以 9 月新生入学为重点场景，通过高频问题收集、官方资料核验、知识库建设、问答入口优化和服务页面跳转，帮助用户更快获取准确、适用、可执行的校园信息。
